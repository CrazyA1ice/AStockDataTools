# Daily Autopilot S4：定向财务缓存九表历史预检

## 用户操作
在三页主界面的“下载 / 更新”选择：增量更新 → 自选1~5只股票 → 仅财务 → 公告日期范围（≤31个自然日）。按钮改为“刷新财务缓存并检查历史（不入库）”。点击后须再次确认；此操作会更新QMT供应商本地缓存，不更改Parquet/H5和财务扫描游标。

## 本阶段增加的功能
在原临时QMT财务缓存worker成功返回后、清理临时JSON之前，调用只读 market_scoped_finance_history_review.py。该工具验证私有临时文件位置和SHA256、正式财务进度账本SHA256、明确的股票/公告日期/9张表/每表行数；然后复用 qmt_extra_financial_cache_import.py 的 `_prior_rows`、`_rows`、严格 `_plan_symbol` 来对每个股票的所有9张表逐表比较历史不可变版本，不接受Capital任何实验性例外。

与导入器不同，遇到一张表历史缺失或修订时仍继续只读检查余下财务表，汇总所有受影响表名和缺失/修订历史记录数，而不是只给第一张阻断表。已有历史版本如果出现不能完全解释的变化，股票状态为 `BLOCKED_HISTORY_CONFLICT`；候选新版本状态为 `CANDIDATE_NEW_VERSION_NOT_COMMITTED`；空缓存或股票缺失为 `SOURCE_CACHE_MISSING`。这些都只是本地缓存对照，不认证来源完整性，也不是多源核验。

## 输出与日志
脚本最多读取5只股票、单次压缩/JSON临时文件≤256MiB、进度账本≤2MiB；所有表历史版本读写规则沿用现有验证接口；九表预检子进程最长90秒。输出逐股票的汇总表名和计数、不含原始财务值。原QMT临时JSON仍在正常/错误清理路径中删除。摘要写入既有 work/afternoon-*-SCOPED_FINANCE-*.log，用户可从“异常与日志”页打开。

## 安全限制
整个动作需要用户点击确认；受正式20:05同名Windows mutex约束并禁止19:50–20:25触发。没有导入器执行调用、没有财务Parquet新版本写入、没有pending/游标变更、没有恢复已阻断历史或调低阈值。比对结果一律 `can_commit=false`；未来真正安全入库需要独立的备份、事务恢复、授权和回归验证。供应商QMT缓存刷新本身会改QMT本地缓存，不能说整个动作是纯只读。

## 本阶段验收
增加16项纯合成测试，覆盖跨多表冲突、缺失股票、缺表、行数和索引异常、非法日期、临时文件目录限定、SHA门禁、显式只读、日志/PowerShell连接。基于S3预计403项，当前预计419项命名回归，但均以用户Windows回归结果为准；本阶段未运行Windows真实更新、没有提交到main或正式部署，不创建第二个每日任务，不用GitHub Actions。
