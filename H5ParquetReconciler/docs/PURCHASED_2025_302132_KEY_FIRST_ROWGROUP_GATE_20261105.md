# 2025 SZ302132 原购买Parquet单证券查询：键先行、OHLCVA严格有界（2026-11-05）

## Windows失效证据
- 普通购买查询18/18 PASS；2025历史时点身份合成测试12/12 PASS。
- 实盘试点查询2025-01-02单只`SZ302132`的5分钟源时，原通用Parquet查询先验计算候选行组需要扫描**64,081,920条**，超过`--max-candidate-rows 30,000,000`；安全退出，**未读取OHLCVA**。原始年份文件页脚行组不能有效将该股单日范围排除至可接受规模。
- **不能简单把30m预算提升至70m**。这会解除原有防护，却不解决受限单股请求放大全年OHLCVA读取的问题。

## 新增独立研究级双阶段查询
- 新`tools/query-purchased-2025-302132-key-first-bounded-readonly.py`，只对2025年 `SZ302132` + `1min/5min`允许调用。
- **阶段一：键先行**。核对原始2025年文件路径、schema、页脚元数据和总记录预算；投影读取原Parquet `ts,symbol` 两列，按具体股票+日期找出包含目标时间键的完整物理RowGroup。允许时间键扫描预算上限**350,000,000条**，覆盖2025年已验收1min来源321,744,640条和5min来源64,081,920条；不读取OHLCVA。读取预算可通过函数参数向下收紧，不可高于硬上限。
- **阶段二：精准行组行情读取**。仅在确切含目标原始代码/日期的RowGroup上打开`ts,symbol,open,high,low,close,volume,amount`。必须在打开任何OHLCVA列之前，证明这些RowGroup物理总行数不超过硬上限**2,000,000**，且不高于原调用的`max_candidate_rows`。绝不直接把大于30m的候选行组输入原通用查询。所有实际返回键必须与阶段一的准确键集合一致，重复、缺漏、量价几何异常和源统计漂移均失败关闭。
- 该修复**没有改变其他八周期查询器的默认行为**，没有修改A股前缀规则、私有索引/H5补缺，不保存OHLCVA缓存或生成市场文件；本机Python返回的授权原始量价仅用于受限研究查询，CLI仅显示来源计数。
- `tools/query-purchased-2025-302132-asof-identity-readonly.py` 现在复用独立键先行查询并附加历史时点身份标注：官方证券代码变更前`SZ300114`，自2025-02-17起`SZ302132`；始终保存供应商原始标签`SZ302132`，绝不重写源代码。
- 新增`tests/test_query_purchased_2025_302132_key_first_bounded_readonly.py` 7项合成测试：强制原始行组元数据无法有效剪枝、验证只打开目标RowGroup的OHLCVA、物理行组预算拒绝、键扫描预算拒绝、空目标不读取OHLCVA、重复时间键拒绝、无缓存/市场源不变。
- Windows验收`run-purchased-2025-302132-asof-identity-smoke.ps1` 现在依次运行原18项+新7项+原12项测试，并对2025-01-02 5min、2025-02-17 5min与1min实盘进行单日研究查询。每条实盘打印`SOURCE_KEY_ONLY_ROWS`、`OHLCVA_ROWS_DECODED`与`TARGET_ROWGROUPS`。
- **以上新修改尚待用户Windows实机验证**。如果实际选中源行组仍超过2m行，工具会报错而不会扩大行情预算。需先查看具体源布局再设计更窄索引/读取方案。
