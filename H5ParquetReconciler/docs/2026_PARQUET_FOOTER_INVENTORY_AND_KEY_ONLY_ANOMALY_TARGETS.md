# 2026-10-27：购买Parquet 2011—2026年Footer实测——完整文件覆盖与2月/8月重点证券日排查

## 用户真实元数据报告：`parquet-primary-footer-inventory-2011-2026.json`

报告由本机只读Footer工具生成，**没有扫描实际OHLCVA或逐股票时间键**。对`AllCycleAStockData/{day,1min,5min}`三个周期统计：

| 周期 | 文件数 | 记录总数（Footer） | RowGroup数 | 文件总容量（GiB） |
|---|---:|---:|---:|---:|
| day | 24 | 14,115,707 | 139 | 0.226 |
| 1min | 24 | 3,447,422,899 | 28,035 | 38.970 |
| 5min | 24 | 686,623,649 | 5,572 | 11.274 |
| 合计 | 72 | 4,148,162,255 | 33,746 | 50.470 |

- **2011至2025**，每年各周期各有1个Parquet年度文件；**2026年1—9月**，每周期有9个分月文件。最早候选日均为**2011-01-04**，最晚均为**2026-09-30**；截至2026-10-27这个购买包的Footer报告中没有2026年10月Parquet更新。
- 非空RowGroup缺`ts`时间范围统计=0；时间边界不属于文件名年份的行组=0；有歧义或缺年份的文件、符号链接跳过与请求范围外的文件均=0。72个文件元数据均支持合法年份/时间范围，**但不等于每个交易日/证券都完整，也不证明行情绝对正确或完整退市股票代码映射**。
- 观察到三周期时间标签分别为日线约**08:00**、一分钟原始09:30到15:00、五分钟原始09:30到14:55；日线08:00是实际源字段的时标，不能直接当作交易开始时间。主查询接口要统一日期解释但保留原始来源时标。
- 每年**2011—2025**购买Parquet的1min总行数可表示为某整数×241、5min总行数可表示为同一整数×48。这是Footer总数算术关系，不是逐个交易日已被认证；它提示供应商可能系统性填满交易时段，不能据此推导每只证券日都真实发生了这么多次交易。
- **2026年2月与8月**出现值得定位的小规模偏差。按2026年标准完整源键组合：2月5min 3,733,025 = 77,771×48 + **17**，1min 18,742,892 = 77,771×241 + **81**；8月5min 5,666,976 = 118,062×48，而1min 28,452,941 = 118,062×241 **−1**。必须核对究竟是哪几只证券、哪天、哪些时间键，**不能仅凭余数判断是漏条、重复、特殊证券或供应商补录错误**。
- 2026年9月30日是**文件Footer右端范围**，不能凭此认定各只股票在最后一个交易日均完整；也不能凭日线与分钟总记录数不同就强行补齐，数据可能包括不同证券类别。

## 下一轮精确诊断：只读按月的(ts,symbol)列

新增`tools/audit-parquet-month-minute-keys.py`：
- 只针对一个年份、一个月份扫描购买Parquet的`1min`与`5min`，基于行组Footer的时间剪枝，**只投影时间戳ts与证券标识symbol两列**，不读取OHLC、成交量或成交额，不写原始文件，也不上传整个股票列表或股价。
- 对每个观察到的标准化证券代码×北京时间日期维护**241位1min和48位5min完整性位图**，严格检查1min`09:30`额外开盘记录+`09:31—11:30`及`13:01—15:00`、5min起始标记`09:30—11:25`和`13:00—14:55`；记录每个证券日的缺失标签数量、重复标签数量、异常时段标签数量。该2026年网格规则由既往抽样支持，**不能擅自推定早期特殊市场/停牌/上市日期也一样**。
- `--universe all`默认研究整个供应商代码集合，同时允许`--universe a-share-candidate`仅检查代码模式上像A股的证券；`all`可能包括指数或其它品种，它们的特殊网格出现异常**不一定意味着A股数据错误**。异常实例最多默认60个，支持`--max-examples 200`，完整异常总量不会被样本截断影响。
- 源读取预算默认每个周期最多5000万条候选行组记录、观察到的单周期证券日≤100万；超出则拒绝大规模扫描、要求显式调整。读取每月原始1m/5m的实际键，**与上轮Footer-only工具不同，必然有磁盘读取成本，但仅包含两列**；不读取H5、不触碰日线、不创建索引/新主库或自动并集，报告仅保存在本模块`reports/`。
- `sample_anomalous_stock_days`记录少量异常的**证券代码、日期、两周期记录根数/正常时段不同标签数量、缺失、重复、超出网格数量**；不包含任何付费原始价量额数据。无论样本是否异常，结果均不代表市场真值或交易所逐笔认证。

## Windows核验（建议先2月，确认后再8月）

从仓库根目录：

```powershell
git pull --ff-only origin main
.\.venv\Scripts\python.exe -m unittest discover -s H5ParquetReconciler\tests -p "test*.py" -v

.\.venv\Scripts\python.exe H5ParquetReconciler\tools\audit-parquet-month-minute-keys.py "D:\stock" --year 2026 --month 2 --universe all --max-candidate-rows 50000000 --read-only --out "reports\pq-key-only-2026-02.json"
```

再运行8月（不必同时跑）：

```powershell
.\.venv\Scripts\python.exe H5ParquetReconciler\tools\audit-parquet-month-minute-keys.py "D:\stock" --year 2026 --month 8 --universe all --max-candidate-rows 50000000 --read-only --out "reports\pq-key-only-2026-08.json"
```

## 之后的实际主库路线

两月精确键诊断后，可在已确认的2026年近端接入**购买Parquet只读查询层**：单证券有限交易日、合理RowGroup成本预算、原时标和标准时标并存、指纹及来源可见、查询输出区分日线和分钟类型。历史主数据优先Parquet，H5只作为确认有数据缺失时的备选，通达信盘后完整交易日进入独立可回滚新增层。**不需要也不应该首先将50GiB源Parquet整个重写一份标准化库。**
