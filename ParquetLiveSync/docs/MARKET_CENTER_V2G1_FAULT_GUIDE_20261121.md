# Market Center V2G1：故障处理可读性与当前页面状态一致性

用户提交了V2G首页与故障诊断两张 Windows 实机截图。四条任务路由已经可用；主要待改进点是：故障诊断页面右侧长门禁说明占满空间且换行凌乱；左侧错误表格的 QMT_FINANCE_CONNECTION_LOST 分类被截断；从「更新行情」任务入口切到侧栏「故障诊断」后，底部依然显示「当前目标：更新行情」，容易误解当前正在执行的操作。

本轮在 V2G 提交 a8dc3f7ae658bec51d381c105d70b53810d98d19 上单独建 Draft 开发分支，严格限界面和测试：
- 故障页右栏改为四条短、独立的中文处理步骤：查看同次错误及日志、手动检查QMT实时连接、核对代码与财务版本、等待受控恢复入口。明确每条步骤只是只读核对，不自动下载或重放跨日财务任务。
- 长的 QMT 门禁、正式版本指纹与历史财务备份描述保留原有动态StringVar，但放在「展开恢复门禁详情（只读）」中；点击展开本身不进行 QMT、文件盘点或资金数据操作。原始 JSON 继续独立折叠且仍可读取。
- 在右栏顶部显示选中的完整错误类别名称，避免左侧表格窄列截断。读取新回执时清除旧类别，防止错误跨回执滞留。
- 侧栏导航每次切页都更新状态栏「当前页面」，避免从更新模式切到故障诊断后仍显示旧目标；「按建议继续」和原四任务按钮仍只负责导航。
- 首页及七页结构不变，20:05生产定时任务、唯一写锁、QMT正式财务下载/游标和行情Parquet、H5数据未修改。一键恢复一直 disabled。

测试：继承V2G已有262个test_方法，新增5项合成 Tkinter 交互回归（四项独立步骤、默认隐藏的恢复条件、侧栏状态一致性、错误完整代码显示和旧功能安全检查），预计267项，须用户 Windows 上完成；GitHub静态检查不能代替实际GUI测试。

重点 Windows 验收：从首页点击「更新行情」，再用侧栏进入「故障诊断」，底部应变成「当前页面：故障诊断」；故障页四条步骤清晰分开，「展开恢复门禁详情」和「展开原始证据」均默认收起；选中 QMT 错误后能看到完整类型；核验仍只读，所有下载/重试写入按钮继续禁用。
