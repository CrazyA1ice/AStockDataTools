# A股统一Parquet日线主线：1990—2010年原始Hikyuu H5历史覆盖只读盘点

2026-11-05，开发分支 `feat/purchased-primary-minute-local-query-20261105`。

## 为什么进入历史盘点

统一八周期研究查询已完成真实Windows验收的三类日线来源：
- 2026-10-09 / SH600000：购买Parquet 0，H5整日补缺 1。
- 2026-04-08 / 隐去证券代码：购买Parquet 0，H5混合股票日补缺 1。
- 2026-04-08 / 隐去证券代码：购买Parquet 1，H5补缺 0；原始购买
  **开高低收/成交量/成交额6字段、毫秒源时间戳和文件RowGroup精确一致**。

**但这仅验收了2016/2026年的22,274条已注册候选**；不能推断
1990年前后到2010年的历史日线已包含在统一Parquet，更不能自动
填入生产。下一步必须先直接盘点原始H5日期范围、证券类别和每年键量。

## 新增只读盘点

`tools/inventory-original-h5-1990-2010-day-keys-readonly.py`
直接在 `D:\stock\HikyuuData\sh_day.h5`、
`sz_day.h5`、`bj_day.h5` 上读取 **native datetime单列**，
不读取OHLCVA，不转换原始H5，不写Parquet/H5、私有候选、索引、
版本/生产指针，CLI仅输出聚合SAFE JSON。

- 研究窗口为1990-01-01到2010-12-31，包括21个年份。
- 只根据已有`CORE.is_a_share_candidate(symbol,year)`规则将
  **A股代码候选**与“指数、B股及其他代码”分开。它不是证券主数据认证；
  不会扩大主线A股代码过滤范围，也不会把指数当作A股。
- 对原始H5中已按日期排序的单证券序列，通过二分键边界限定
  1990—2010的物理H5切片，再按最多16,384行/块仅读取datetime；
  验证选中区间内的YYYYMMDD0000格式、闰年日期、严格单调/重复，
  以及源文件读取前后size/mtime未漂移。
- 输出每年候选股票日键数、候选证券数、不同日期数、非A股代码键数、
  上交所/深交所/北交所分布，及整个21年总计。**不输出任何证券代码、
  原始量价值或私有83条键**。
- 对未满足H5 schema、出现重复日期、文件或源数据变化、
  无法限定的读取预算均失败关闭。默认最多读取30,000,000条
  历史native时间键；超过只报错，不默认提高预算。
- 标记是否存在1990以前的原生首键，但本轮不清点其完整年份；
  不声称H5所有年份全局排序均已独立证明，只检查选中区间的严格递增。
- **尚未单独核查2011以前购买Parquet是否存在历史文件、原始数据是否
  属于交易所当时有效A股证券身份、复权价格/成交量因子、官方交易日历、
  历史停牌或IPO上市日期**。所以即使得到键总数，亦不得直接认定
  它们全是可生产补缺的合法市场股票日。

## Windows验收

- `tests/test_inventory_original_h5_1990_2010_day_keys_readonly.py`：
  10项全虚构临时H5测试，覆盖A股/指数/B股/BJ分流、1990年前
  原生首键、源文件不变、2011以后数据跳过、日历非法、非午夜、
  重复/无序日期、budget超限及缺失/符号链接数据源。
- 单条入口：
  `H5ParquetReconciler/run-original-h5-pre2011-day-history-inventory-readonly.ps1`。
  先运行上述测试，再执行一次完整**时间键单列**盘点，只打印
  有覆盖的年度总计、最早原生首键、分类计数和原始文件stat SHA。
- **新工具与10项测试尚待用户真实Windows验收**。这次会读取
  源H5的原始datetime，可能比轻量文件头审计耗时，但不会读取量价。
  错误时不创建部分历史Parquet，也不会有未经验收的生产回写。

## 根据真实覆盖结果的下一阶段

1. 根据年度起止、A股代码候选年总量核对H5对历史区间实际覆盖。
2. 单独只读盘点购买Parquet的早于2011记录和所有可能的日期文件/
   RowGroup，再判断哪些H5历史股票日可称为“Parquet缺失”。
3. 对当时有效的证券身份、官方交易日历、原始H5缩放量纲和复权语义
   进行进一步验收；建立私有分区和不可变版本后，才可能讨论
   对历史日线的**生产级Parquet补缺**。不能直接把这次扫描计数合并。
4. 2025 SZ302132分钟RowGroup性能问题保持独立，暂不阻塞历史日线主线。

当前坚持：**购买Parquet为主、H5补缺；先只读证据，再私有候选与SHA验收，
最后才考虑生产合并及Parquet→H5镜像。**
