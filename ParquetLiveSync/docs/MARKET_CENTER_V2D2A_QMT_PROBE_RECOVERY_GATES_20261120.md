# V2-D2A：QMT 当前连接检查与恢复门禁分层展示（2026-11-20）

继承 Windows 用户已实际验收的 V2-D1：126/126 合成测试通过、真实2026-11-20统一更新回执成功识别QMT_FINANCE_CONNECTION_LOST（失败批次000756.SZ/000757.SZ/000758.SZ/000759.SZ/000761.SZ、最后日志检查点000755.SZ，private进度账本游标000755.SZ），以及ADJUSTMENTS_ROTATION_PENDING正常轮换，截图首页和故障诊断页布局功能正常。

## 用户反馈与本段目标

截图：正常轮换已与财务执行错误区分、可点击“查看原始日志”“复制安全续跑预览”，但JSON的 blockers=[] 容易让用户以为可以立刻恢复；界面大面积空白表格与黑色JSON占空间过多。需要让用户自主检查实时QMT状态，逐条提示真正尚未达成的恢复前提；绝不能自动开始历史下载。

新增：
- market_center_v2_qmt_live.py：只有用户主动操作才调用原生产已存在的 qmt_connect_preflight.probe_once()，它使用**独立子进程**进行一次 xtquant.xtdata.get_client() 连接检测（默认15秒，最多25秒），不下载任何行情或财务，不访问市场资料也不修改账本。测试仅以模拟函数运行，不连接真实QMT。
- 北京时间19:55-20:20系统保护窗内直接阻断，连连接探测都不启动。超时、连接不可用、供应商异常均返回明确状态；连接成功仅意味着该时刻get_client()成功，不代表未来稳定。
- 将原静态 blockers=[] 和四个未完成执行门禁严格分开：首页和“故障诊断”页展示五项：①同次证据/游标（通过或阻断）；②QMT实时连接（未检测或已观察到）；③正式计划任务独占写锁；④canonical财务重试代码与固定SHA；⑤财务快照备份、可回滚性。**后三项从不因为连接成功而自动变成通过**。
- GUI首页和故障页均有“检查QMT当前连接（不下载）”按钮。检测只在点击时由后台短任务执行，Tk主线程定时读取队列；刷新正式任务回执时会清除既有的连接证据。复制安全恢复预览时重新读取最新回执并比对SHA；只有匹配才附上之前的连接时点观察。实际“一键重试”按钮仍禁用，更新历史、清空游标、删除版本均禁止。
- 将故障列表的Treeview高度从9行调至5行，不再纵向占满所有空间，恢复条件和原始证据更易同时看到。
- market_center_v2_qmt_live_cli.py：可选显式 --state-module 与 --explicit-connect-only，经过只读正式回执核对后才单次连接，输出结构化 JSON。若没有明确opt-in或者回执不存在则不启动连接探测。

## 必须保留的边界

- 原20:05单触发自动任务、原行数据更新器和财务提交器均不更改，不部署PR #221断连补丁到canonical；正式导入器实际续跑功能仍没有开放。
- get_client()是供应商服务探测，不应称为零QMT连接次数，但下载次数恒为0、行情/财务写入恒为0。
- 静态证据门禁即使通过，也只是最新本地同次回执和账本核对，不是来源真实性、市场完整性、QMT持续在线、可执行性认证。
- 跨到北京时间2026-11-21之后，原11-20财务daily检查点只供诊断，不能直接重放“昨天的今日增量”。既有V2-D1的日期门禁仍会阻断，不应用当前QMT连接成功绕过旧日期恢复限制。
- 自动任务20:05的唯一写锁保护不变，连接检查不能授予写锁或启动任何财务作业，独立部署审核与财务版本备份留到下一阶段。
