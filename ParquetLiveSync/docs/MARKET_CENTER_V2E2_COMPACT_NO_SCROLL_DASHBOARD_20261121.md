# V2E2：紧凑首页及按需滚动策略（2026-11-21）

## 来源

用户 Windows V2E 整合版 ecb20da6131f45bca5e5349891e393fed2f1e9a3 已全部跑通 **229/229 离线测试**，并提交七页真实 GUI 截图。截图显示：深蓝侧栏、三步更新核验、双栏核验/故障、日志均正常；但首页将 KPI、三类判断、变化、四阶段、故障、按钮由上到下堆叠，右侧固定垂直滚动条，底部两个只读检查按钮甚至被页面下缘遮住。数据管理与高级设置在普通大屏也常显滚动条，尽管内容仅占上半屏。

## 设计决策

以用户已选 V2E 七页布局为基准，仅进行 Tkinter 展示层重排；保留原所有数据源、鉴权与20:05唯一自动更新任务。

### 首页：无外层滚动容器（优先级最高）

- 顶部：一行最近一次运行主题 + 4 张状态卡，下一行同轮开始时间。
- 中部左右两栏：
  - 左栏：「三类结果独立判定」三列横排，下面「本轮四个阶段」2×2卡片；
  - 右栏：「本次可信变化」简短说明 + 「常用操作」；四个导航动作2×2，两项 QMT实时连接/正式版本备份只读检查各占独立一整行。
- 底部：单个短的「待处理事项与下一步」故障区，右侧财务待审数，下面保留本轮错误说明、静态门禁、即时QMT状态、正式指纹/快照盘点状态。详细失败批次、完整 JSON 和原始日志仍在各自独立页查看。
- build_home() 不再调用 _scroll_content(self.home)；self.home 下直接加入标准 ttk.Frame，没有总览页外层 Canvas / Scrollbar。同时保留所有原动态属性，以便原 refresh_overview、refresh_fault_diagnosis、QMT/财务检查按钮无需改后端就能工作。

### 数据管理与高级设置：能放下就不显示滚动条

- 调整公用 _scroll_content：根据 inside.winfo_reqheight() 与 canvas.winfo_height() 判断内容是否真的超出；内容可完整显示时 scroll.pack_forget() 并复位顶部；只有缩小窗口、系统高DPI等内容溢出时临时显示垂直滚动条。
- 核验结果、故障列表、原始证据、运行日志等仍有内部垂直/水平滚动，这是必要的长内容浏览，不应禁止否则会裁切证据。

## 本轮安全边界及验收

- 新版本分支以已通过229/229 Windows测试的 V2E ecb20da6131f45bca5e5349891e393fed2f1e9a3 为基线；不修改 market_center_v2_preview.py、任何QMT worker/CLI/财务历史文件、named mutex或唯一20:05调度脚本。原V2E整合工作树保留，新的 detached 工作树单独验收。
- V2E2 在原 229 项上新增 3 项展示合同/GUI合成测试，理论 **232 项**，尚未在 Windows 实测，不得把新增项称为通过。
- 检查普通桌面分辨率例如 1655×900 的首页：底部告警、财务待审和全部六个按钮不需滚动即可见；数据管理和高级设置在能容纳内容时无占位滚动条。再次检查 QMT 探测仅点击后开始、一键恢复依然禁用。
- 小窗口下以不裁切为优先；数据管理和高级设置仍有按需滚动兜底。首页不应该因为内容重排丢失任何后端字段。
