# A股数据更新与核验中心 V2.0 · 设计基准（2026-11-20）

> 状态：用户已确认的默认设计，可在后续迭代修订。方案采用 **A 卡片总览 + D 监控/操作**，建立在现有 20:05 更新程序之上；当前 Draft 分支不修改生产计划任务。

## 一、核心目标

**看清每次自动任务实际改变了什么；关机漏跑后能受控补更；对某一时间段或若干股票进行定向更新或核验；从异常摘要追溯完整证据日志。**

交互顺序：运行总览 → 选范围 → 预检/执行 → 看本次变化/异常 → 展开证据。首页不显示冗长参数、完整 JSON 和异常堆栈。

## 二、页面与信息层次

| 页面 | 首页主内容 | 操作 |
|---|---|---|
| 运行总览 | 最近任务时间/状态、已提交最新交易日、与上次相比的变化、QMT最近预检、待处理异常 | 立即更新、数据核验、查看日志 |
| 更新 / 核验 | 单一共享日期范围、股票范围、数据类型、来源只读说明、任务预览 | 两模式切换、能力检查、执行 |
| 历史日志 | 按运行/阶段聚合的结构化摘要、失败原因；原始日志可展开 | 查看具体异常、打开本地日志 |
| 数据管理（后续） | 八周期覆盖、历史缺口、版本冲突/隔离、财务时点真实性 | 历史段只读核验报告 |
| 高级设置（后续） | 原定时任务和默认参数 | 二次确认后更改 |

### 首页只强调“变化”

1. 最新**实际提交**交易日；上次任务结果和日期；北京时间当前安全上限；QMT**最近一次**连接预检；财务待审。
2. 本次比上次：已提交交易日推进、各阶段有没有新增、财务待审 X→Y、隔离异常新增/减少。无可靠前后快照时显示“暂无可比证据”，**不得虚构增量数和完成比例**。
3. 四阶段极简状态：八周期行情、板块、除权、财务。详情及原始日志收至下级页面。
4. “任务执行 SUCCESS/PARTIAL/FAILED”、“数据核验 PASS/PARTIAL/FAIL/UNVERIFIED”、“跨源状态 PASS/UNVERIFIED/FAIL”三者**独立**呈现，不能因退出码为 0 就宣告数据完全可信。

## 三、同一表单承担“更新”和“核验”

**只有一组时间段：开始日期、结束日期（含两端）**。更新/核验切换时**保留**日期、股票列表、数据类型，不复制第二组日期。

- 操作模式：更新数据 / 数据核验。核验应是纯只读作业，绝不借核验名义下载或覆盖行情文件。
- 数据类型：八周期行情（分钟 1/5/15/30/60、日/周/月）、板块、除权/复权数据、财务。
- 股票维度：全部股票 / 指定股票。指定股票允许 1 只或多只，支持批量粘贴、删除、去重、显示已选择数量。第一阶段只接受六位代码加 .SH/.SZ/.BJ；六位纯数字不能猜测交易所。正式执行时应进一步要求股票属于已认证的冻结股票池。
- 日期使用北京时间 20:05 安全边界；月线必须闭合；未来日期/逆序日期拒绝。交易日校验由原更新引擎负责，不在 GUI 猜测节假日。
- 模块选择在两个模式之间共用。若组合的按日期/按股票执行能力没有被底层核验，不得悄悄退化为全市场写入。
- **历史段核验** 后续接入：缺失股日键、1/5min 时间格、OHLCVA、一致性、重复记录、已购对照源、版本指纹、财务公告时点等；尚未接入时清楚标“待实现”。

## 四、数据来源：自动选择、公开显示、不让用户手选

真正的配置来自 ParquetLiveSync/market_sources.json 或本地 work/market_update/sources.local.json，真实执行成功来源以当次运行回执为准。

| 类型 | 更新来源 | 可显示的核验/参照来源 | 边界 |
|---|---|---|---|
| 分钟行情 | QMT 与已购分钟数据、SHA 钉住的历史校准 | eltdx（TDX 7709 OHLCVA 抽样）、腾讯 m1（OHLC/时标抽样，无金额） | 配置可用不等于核验通过；akshare 默认 disabled |
| 日线 | 已接受的 TDX 官方 DAY/本地叠加 | 采购口径/已存在的比对证据 | 不能宣称 QMT 分钟就是官方日线 |
| 周/月线 | 已接受日线派生、已购校准规则 | 已购 WEEK/MONTH 校准锚点 | 仅自然周期闭合后发布 |
| 板块/除权/财务 | QMT 对应服务/缓存 | 尚未有完整独立跨源认证 | 保持“未独立核验”，44 历史冲突及 688259.SH UTF-8 异常仍隔离 |

仅当日志真实产生了对应 SOURCE_SAMPLE 证据时标记该轮抽样通过，不能把静态 enabled 当成跨源 PASS。

## 五、已支持与未接入能力（必须诚实显示）

| 场景 | 现有能力 | V2-A 第一阶段 |
|---|---|---|
| 原唯一 Windows 20:05 四阶段增量任务 | 已部署、连接就绪探测与共享 mutex | 保持不变，不创建第二任务 |
| 现有 GUI 全市场补更到当下安全截止 | 已有统一 runner 和原 GUI | 旧 GUI 保留；新 UI 暂不调用原 runner |
| 任意起止日与任选股票对行情/财务写入 | 四个阶段接口不统一、可能破坏历史门禁 | **只展示计划，不允许生产写入** |
| 指定历史段/指定股票核验 | 有独立审计工具，尚无统一只读 API | 先展示输入和待接入能力，不伪称完成 |
| 本次与上次之间各项数据真实变化量 | 缺少全面可审计前后快照 | 证据不足显示“暂无可比证据” |

## 六、生产安全原则

- 唯一原任务 AStockDataTools-ParquetLiveSync **北京时间 20:05**，现有计划任务脚本、路径、触发器、登录会话及原 Dashboard 保持不变。
- 既有 commits.json、财务进度、QMT DAT、H5/Parquet 不删除、不覆盖，不绕过历史冲突、校准 SHA、源时点及隔离规则。
- 新 UI V2-A 仅读取本地指定状态 JSON 和来源配置（有预算限制），不启动 QMT、不执行下载、不改数据库、不写历史数据。仅通过本地用户明确操作确认后，未来阶段才开放获批后端写入。
- GitHub 只提交代码/文档/合成测试，不上传用户的私有数据、账号、缓存、日志或凭据。
- 所有 UI 输出区分“实际当前在线”与“上一次日志的 QMT 连接状态”；不能用 0 行月线认定当前未闭合的月缺失。
- 独立 Draft PR 与 detached worktree 验证，用户 Windows 未通过前**禁止合并到正在运行的 canonical 代码**，不执行任务安装和 Apply。

## 七、迭代安排

- **V2-A（本轮）**：设计基准文档 + 单独启动的极简 Tkinter 原型：首页真实状态快照、共享时间段与股票多选、更新/核验模式、只读数据源说明、计划预览与功能门禁、纯离线测试。
- **V2-B**：按股票/时间/周期的只读历史核验 adapter，并有可见证据覆盖、时间格与异常报告，正式核验不得修改原行情文件。
- **V2-C**：分阶段适配定向增量写入，逐一实现和验收 dry-run、范围守卫、独占锁、事务、冲突隔离、校验与日志。
- **V2-D**：对可信的运行前后摘要生成有版本号的本地快照与增量差异；收起复杂参数，强化异常导航。

### V2-A 验收口径

两种模式共用同一日期/股票/模块状态；股票支持批量输入、去重、校验；只读来源来自配置而非静态臆测；计划预览可复制但**不能执行未获支持的数据写入或核验**；首页不显示完整日志；对任何未知真实变化显示“暂无可比证据”；旧 GUI、20:05 唯一任务和原所有生产脚本未被更改。

> 这是用户在 2026-11-20 确认的阶段设计基线，不是最终不可更改的产品规范。后续按单独 PR 审核迭代。
