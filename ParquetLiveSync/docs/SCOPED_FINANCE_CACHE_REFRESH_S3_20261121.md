# 三页主界面：指定股票财务缓存增量刷新（S3，开发草稿）

## 本阶段允许
在下载 / 更新页选择 增量更新 → 自选股票 → 只勾选财务 → 指定公告日期段（最多5只，最多31个自然日），会激活“刷新所选QMT财务缓存（不入库）”。用户点击后必须再次确认。此按钮与原有“按既有游标继续更新”彼此独立。

执行脚本：run-scoped-qmt-finance-cache.ps1。调用已存在的 qmt_extra_financial_cache_worker.py --mode daily，使用 QMT download_financial_data2 在用户选定公告日窗口增量刷新其本地缓存。**QMT客户端自己的财务缓存会改变**。工作进程短时写入用户本机私有 work/qmt_extra/scoped-cache-stage 随机目录，正常退出/错误处理时清理临时JSON。正式财务Parquet、H5、游标、pending及历史版本不提交、不重置，也不授予历史冲突的豁免。

## 不与20:05正式任务抢写
PowerShell 脚本要求正式仓库 .git 目录存在，审阅用 detached worktree 不允许执行；与正式任务共用 Local\AStockDataTools2005AllStages 命名互斥锁，不可并发；北京时间19:50—20:25禁止触发，其他时间执行也须在300秒内结束；脚本重新验证股票格式、数量、日期及截止日。下载过程中不启动第二个计划任务。

## 日志
写入 work/afternoon-*-SCOPED_FINANCE-*.log。仅包含股票数量、公告日期窗口、成功时的临时JSON摘要/大小，或失败代码和原因；不输出报表原始字段值。旧版日志列表能匹配 afternoon-*.log，因此三页界面的异常与日志页可选中查看。强制掉电、杀进程可能导致未清理的临时原始数据，需要后续补充启动时安全清理，不宣称任何崩溃都能零残留。

## 尚未开放
全市场指定日期及分周期行情/板块/除权的任意范围重下仍未实现；仅财务自选范围可以更新QMT缓存，不是正式金融数据库入库。原有全市场按游标安全续更独立保留。重新下载并比对模式不会覆盖旧快照，不能以本地缓存完成代替跨源校验。
