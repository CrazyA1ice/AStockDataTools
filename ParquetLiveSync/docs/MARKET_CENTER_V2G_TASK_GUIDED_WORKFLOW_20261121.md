# Market Center V2G：任务导向工作流（2026-11-21）

## 背景与目标

用户实际 Windows V2F 七页 GUI 截图表明：界面已能显示 2026-11-20 的 PARTIAL 任务、八周期/板块通过、财务 QMT 连接中断，以及只读证据链和安全门禁。但是首页把技术能力堆在一起；“更新 / 核验”页历史策略与范围设置过于复杂；“故障诊断”右侧先出现大段原始 JSON，常见操作的顺序不直观。

在不修改技术后端的前提下，**让用户先回答“我要做什么”，再由 UI 引导到正确页面与下一步**。V2G 从已修复 V2F 单元测试的固定提交 7b30c4274d82873482ffd3e08cdf8ceab028ac9c 创建独立开发分支，不覆盖任何正式安装文件。

## 四条任务路径

| 首页入口 | 用户看到的工作路径 | 当前许可 |
|---|---|---|
| 更新行情 | 选择方式和日期 → 选择股票和数据类型 → 核对只读计划 | 仅预览，不能下载或写入 |
| 检查数据 | 选择“数据核验”和日期 → 指定股票和数据类型 → 选择八周期之一并启动受限只读扫描 → 查看核验结果 | 一次最多20股、31日，源范围和时间保护由现有后端负责 |
| 处理错误 | 查看同次故障及批次 → 按需QMT即时连接检查 → 核对正式版本与财务备份范围 → 等待独立审核后恢复 | 仅诊断，任何重试/跨日财务重放仍禁用 |
| 管理数据 | 查看八周期和来源状态 → 理解未逐周期认证 → 如需证据则转“检查数据” | 只读 |

导航路由及每一步的中文说明放在纯模型 market_center_v2g_workflow.py 中。该模型不导入QMT，不启动下载进程，不访问财务文件，不具备提升执行权限的接口。

## 真实GUI中的改动

1. 首页右侧由六个同权操作按钮改成四个清楚的任务入口（两列两行），分别注明“仅计划预览”“只读可用”“仅诊断与只读检查”等限制。点击只切换页面或现有向导，不会自动启动QMT或历史行情扫描。
2. 基于最新只读正式回执提供一个推荐下一步：任务执行PARTIAL/FAIL优先进入故障诊断，数据质量FAIL优先进入只读核验，无回执时也只建议检查数据，不假定任务成功。推荐按钮只执行导航，并不会自动修复。
3. 原首页两项QMT/正式版本技术检查保留，但默认收入“高级只读检查”折叠区，只有用户主动展开并再次点击才执行；故障页原独立按钮仍在。现有 QMT get_client 探测与独立日志/游标/锁/备份门禁不变。
4. “更新 / 核验”三步向导上方增加当前目标路径，且切换更新/核验单选框时文字同步切换；错误提示说明“更新模式只是只读计划，写入未开放”。
5. “故障诊断”右栏先给出四步通俗处置顺序。底部原始JSON改为默认收起的“原始证据（技术详情）”，点击再展开；原内容仍然实时读取，未删证据、未删查看日志和备份预检功能。
6. 保留原七页、八周期卡、局部表格/日志滚动；首页无外层Canvas/Scrollbar，页面高度变化来自内容本身。故障数据和未知来源不得以绿色成功展示。

## 安全与已知事实

- 2026-11-20正式财务阶段断连案例已从同次回执核对到失败批次、000755.SZ游标。跨日不能把旧日增量任务直接重放或清空进度；原金融导入器已有跨日未完成扫描延续机制。即使即时 QMT 连接成功，也不代表可以执行财务恢复。
- V2G仅做页面路由和证据展示，不修改20:05正式调度、唯一写锁、行情/财务Parquet或H5、财务缓存/Worker及其真实版本、QMT正式连接策略；不调用任何自动修复、下载或备份写入。
- V2G仍处于只读预览阶段；“更新行情”只是配置与计划预览，不是假装已经启用了手动更新。
- 对“全部股票”选择，实际受限核验仍受后端最多20股与31日约束，不能因为首页快捷入口改变安全限额。

## 验收与下一步

用户已完成 V2F 的 240/240 Windows 离线回归。V2G新增 9 项纯工作流模型测试、13 项Tkinter导航与技术详情合成测试，合计 **262 个 unittest 测试方法**（需 Windows 执行，未实测前不可宣称通过）。

建议在新的 detached worktree 下运行完整回归后打开 GUI，重点点击：
- 首页四个任务入口是否进入正确页面且没有开始下载；
- 推荐下一步在 PARTIAL 时是否自动强调“处理错误”，点击后是否只进入故障页；
- “更新 / 核验”手动切换单选框，顶部向导提示是否一致；
- 高级只读检查默认折叠，展开不调用QMT，仅点击探针按钮才可能真正连接；
- 故障页原始JSON默认折叠，按需展开后仍能阅读同次证据；
- 一键重试始终禁用、原20:05任务和正式Parquet不变。

下一阶段仅在本次导航验收后，才考虑更高级的只读核验报告、交易日历认证、正式审批过的受控执行器。不能把UI上通俗的“更新行情”误认为已拥有下载许可。
