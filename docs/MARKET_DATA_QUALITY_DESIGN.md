# 行情数据管理与质量修复体系设计规范（长期基线）

> 状态：提议中的仓库级设计基线；不以单个交易日或单个数据商作为长期功能边界。面向 AStockDataTools 的 H5ParquetReconciler、ParquetLiveSync 及后续行情管理模块。实际发布需通过对应 PR 验收，不能把本文件视为当前生产已经具备全部能力。
>
> 提议日期：2026-11-25。设计优先级：长期管理与清洗能力 > 个别日期补丁。任何开发者或 AI 后续遇到异常，应先按本规范归类并扩充通用规则及回归测试，不直接为某一天或几只证券拼接不可复用脚本。

## 1. 产品定位和范围

**AStockDataTools 是持续维护的 A 股行情数据库管理、清洗、对齐、质量审计、可追溯修复与增量维护工具，不是 2026-11-25 专项处理脚本集合。**

长期覆盖：
- 数据资产：原购买 Parquet、Hikyuu H5、QMT 本地原生行情、官方 DAY 与经授权的其他独立来源；
- 八周期：1min、5min、15min、30min、60min、day、week、month，且对每周期保留原始来源的单位与时标；
- 生命周期：初始导入、全量/增量对齐、缺口发现、异常隔离、来源交叉核验、修复候选构建、正式审批准入、跨周期/跨格式镜像、质量回归、归档和恢复；
- 范围选择：任意合理交易日区间、任意允许的证券集合、任意具备凭据的数据源及任意可适用规则版本；不能把日期、证券代码、固定股票数量、分区路径或运行回执作为通用核心的硬编码条件。

仓库的私有付费数据、真实行情缓存、用户账户密钥和本机交易数据库**不得上传 GitHub**。发布源代码、合成测试、规则与脱敏的统计证据。H5 和原购买 Parquet 应保留不可变基准；任何变更须另有授权与可恢复的事务。

## 2. 数据模型与来源标识

基准主键为 `(period, symbol, timestamp)`，先按真实原来源的北京时间时间标签/聚合规则核对；日线及其他周期的时标不可直接假设相同。观测与问题登记用更高一级主键：

`(trading_day, period, symbol, source_id, rule_id, rule_version, source_snapshot_id)`。

每次诊断或修复候选应尽可能记录：
1. 源别、接入适配器版本、原格式、请求窗口及（如适用）数据权限、原始文件真实 SHA256、实际源对象路径或不暴露路径的私有引用；
2. 校准凭据：价格复权口径、时间偏移/聚合粒度、成交量及金额单位与倍率，官方 DAY/独立校验样本及其 SHA/覆盖范围；
3. 交易日历、证券映射和当日应有股票集合的来源与版本；`非交易`、`停牌/零成交参考报价`、`缺源`、`尚未下载`、`时间网格不全`必须分开；
4. 规则版本及检查值：预期/实际行数、时间标签唯一性、OHLCVA 合法性、OHLC 与日线聚合对照、amount/volume 单位、跨周期总量守恒、来源冲突；
5. 原始问题、候选修复动作、前后差异、重新校验结果、候选/正式文件 SHA、审批记录和可恢复操作 ID。

**注意：对结构化诊断 JSON 求出的 SHA 只能证明报告快照的内容，不能冒充原始行情字节 SHA、独立行情源签名或交易所认证。** 每类摘要必须标注覆盖范围。不得从旧状态推定最新可用性，也不能凭任务退出码 0 推定数据完整。

## 3. 分类规则：可复用而非逐日特判

异常分为稳定的规则类别，具体细节用证据参数记录，不能靠某一天的异常文本当作全部产品需求：

| 规则类别 | 典型检测 | 处理方向及限制 |
|---|---|---|
| SOURCE_UNAVAILABLE | QMT/API/文件不可达、认证或限流 | 单独标识来源故障、重试许可与冷却；不认为股票无交易 |
| MISSING_STOCK_DAY | 独立官方交易证券列表中有股票，原 1min/day 不存在 | 比对多日覆盖、源缓存及停牌状态；仅在有权限时定向补取，不允许虚构 240/241 根 |
| INCOMPLETE_TIME_GRID | 240/241/48 根与各市场真实交易格点不符、重复/错时区 | 来源原时标检查、合法会话转换；缺格隔离，不按前收插值 |
| PRE_TRADE_QUOTE_OPEN | 09:30～首成交前为零量零额参考报价；开盘字段与官方不同 | 只读首个真实成交分钟诊断，严格对照官方及成交后 HLC；不能直接覆写原始分钟或替代官方 |
| OHLCVA_MISMATCH | 官方/付费源与实际物化的开高低收量额有差异 | 逐字段独立量化，核查时间聚合/复权/单位/来源，不降通用容差掩盖错误 |
| UNIT_OR_CALIBRATION_DRIFT | volume/amount、时标、价格单位或分组规则漂移 | 重新用足量独立重叠样本校准，按来源/周期/时间分段保存版本；未经校准不得混用 |
| ZERO_TRADE_REFERENCE | 只有参考价格而成交量与金额同为零 | 记录为零成交报价或占位，不能伪造有效成交 K 线；量额一正一零须拒收 |
| CROSS_PERIOD_INCONSISTENCY | 分钟聚合与5/15/30/60m/day/week/month冲突 | 按真实时间网格聚合、量价额守恒检验；保护跨月/缺交易日周期 |
| SOURCE_CONFLICT | 两个独立来源价格/量纲冲突或来源有修正 | 保留所有来源、出处和时间版本；除非有正式规则与证据，不自动判定赢家 |
| STORAGE_OR_RECEIPT_INTEGRITY | Schema、文件 SHA、收据、唯一主键或事务状态不符 | 立即阻断写库，取证并按备份/意图日志恢复；禁止覆盖损坏证据 |

不同证券、周期、日期可组合触发多项规则。每条规则都应有 `applicable / detected / insufficient_evidence` 等显式状态，避免仅凭某个先发生的异常遗漏后续字段。

## 4. 标准处理状态机与准入门槛

`OBSERVED → CLASSIFIED → QUARANTINED → REPRODUCED → CANDIDATE → VALIDATED → APPROVED → STAGED → COMMITTED → VERIFIED`

- **OBSERVED/CLASSIFIED**：只读取证、关联官方证券日历和源凭据，标明精确股票日/周期；不会因为暂时不可达即标记数据损坏。
- **QUARANTINED**：原始行情、原旧收据、已接收股票数据与历史基准均不覆盖；故障股票日单独登记。隔离对正式八周期质量汇总仍为 PARTIAL/FAIL，不能用任务执行成功掩盖。
- **REPRODUCED**：同一固定输入及规则版本重新得到相同错误；区别静态数据错误和时间敏感的源缓存变化。
- **CANDIDATE**：尽量复用泛化修复算子（定向补取、首真实成交价确认、单位重校准、时标规范化、跨源核对等）；默认只读预览。若必须持久化，仅写到独立、版本化、不会覆盖旧文件的私有候选目录并生成新的 SHA 收据。
- **VALIDATED**：重新执行原始网格、原有严格 OHLCVA 容差、成交量额、唯一键、来源独立性和八周期一致性检查，包含负例/边界回归测试。**数据源返回完整行数不等于验收通过；首次成交价相同也不等于可以入库**。
- **APPROVED/COMMITTED**：持久写入必须有明确授权、源完整性与恢复备份、隔离清除策略、冲突处理、独占锁、原子提交与前后 SHA/收据；下载写入 QMT 自有缓存与写入项目数据库为**两种不同权限**，不可相互推定。
- **VERIFIED**：在真实物理文件中按范围复读、核查完整数量/内容/交易日/周期，验证无重复和没有影响无关股票日，成功后才能关闭对应隔离；只允许更新针对已修复范围的质量状态，保留失败与审计历史。

缺少授权或关键证据时必须停止在当前状态，允许长期保留 `QUARANTINED`。不得用某次调试成功、单测通过、日志未报错替代物理数据库准入。

## 5. 可扩展诊断和修复插件接口（目标约定）

通用内核负责范围选择、规则注册、证据身份、质量报告和状态迁移，不把具体证券、日期及 QMT 请求嵌入内核。建议接口：

- `SourceAdapter.inspect(scope) -> SourceSnapshot`：默认只读，报告实际覆盖、源 SHA/引用、单位、时标和能力；独立于具体来源。
- `QualityRule.check(snapshot, reference, policy) -> Finding[]`：纯函数或只读函数，包含规则 ID、可复现输入、严重级别、实际/预期与是否证据不足。
- `RecoveryPlanner.propose(findings, capabilities, approval) -> Plan`：默认 `NO_WRITE`；自动限定股票/交易日/周期、供应商流量与回滚边界。
- `RepairOperator.preview(plan, immutable_inputs) -> Candidate`：先在内存/私有区生成新版本候选，保留原始记录；不宣称可以物化。
- `Validator.evaluate(candidate, authoritative_reference) -> Verdict`：完整时格、六字段、跨周期、原购买校准与物理键；结果是 `VALID/REJECTED/UNVERIFIED`，绝不按打印日志的好看程度给 PASS。
- `Committer.apply(approved_candidate) -> CommittedReceipt`：必须有独立权限、互斥锁、原 SHA、备份、全量回读、原子替换和恢复路径；未经验证不得在此层补洞。

优先把通用诊断分类、计划生成、严格来源凭据和可复用测试做成无 QMT/网络/Parquet 写入副作用的核心模块；数据商适配器与有副作用的下载/提交操作单独实现并强制授权。所有本机绝对路径来自配置，不写死 `D:\\ChatGPT`、`D:\\stock`。

## 6. 持续运行与历史修复策略

1. 增量任务正常跑全市场时，同步产生按日期/周期/来源的覆盖统计、异常桶及哈希收据。异常的存在不能把其他已验有效股票数据误判为不完整，也不能将全市场质量标成完全 PASS。
2. 增设**跨日/跨月复检队列**：按证据可用性、异常类别、重试冷却、修复代价和优先级选择待复核股票日；只复核未解决或新源版本可用的范围，不全库反复刷取。
3. 定向恢复从“原始缺口登记 → 最新来源能力复核 → 受控下载/转换 → 私有候选 → 原校验 → 物理事务 → 质量状态复核”走完整路径。不得删除私有原收据然后重跑来伪造首次成功。
4. 为每种已确认机制增加**多日期/多证券、正反边界、供应商异常、重复运行、源 SHA 变化**的合成回归。一次问题若揭示通用机制缺陷，应修通用规则并回归历史相似股票日；不写一次性正式修复分支后弃用能力。
5. 定时任务、GUI、只读 CLI 应使用同一质量状态/分类；“执行结束”与“业务质量完全通过”分开显示。文件及状态历史尽量保留可复核哈希；新闻/消息推送不属于行情修复的默认副作用。
6. 依次验收：离线规则单测 → 隔离合成 E2E → 固定源 SHA 的真实只读审计 → 经独立授权的限范围缓存下载 → 私有可回滚写入 → 真实物理源对照 → 单独批准的生产入库。GitHub Actions 不是必要条件，不得因缺 Actions 跳过验证。

## 7. 2026-11-25 九只股票仅作为回归用例

这一日已知：官方 DAY 5215 只、已接收 5206、隔离 9。两只 SH605336 与 SZ300462 的 QMT 09:30 及首笔成交前部分分钟为零成交参考报价；首个真实成交分钟分别 09:32 开 7.62 和 09:33 开 9.40，严格匹配独立官方 DAY，但**当前普通 241→240 转换后仍拒绝 open**。另七只 SZ300119～SZ300125 的 QMT 11/20、11/23、11/24 各 241 根，11/25 均缺失。这里的数据只属于特定版本下的真实观察，不是全市场通用值，也不能写入通用内核常量。

将这两种故障形成泛化规则和多日期合成测试，历史案例固定为测试 fixture；任何用例的 `candidate_only` 都不能清除九只原始隔离或自动使质量门禁 PASS。未来遇到别的日期或证券时必须沿同一规则，而不是复制并改写这一天的股票名单脚本。

## 8. 近期交付顺序及验收定义

- **P0：持久设计基线与纯函数质量内核。** 本文件先落在独立设计 PR；在正式行情开发分支新增通用 `scope / finding / read-only plan` 组件，零下载、零项目写入，至少覆盖不同日期/证券/周期、多故障并发与拒绝无独立凭据。
- **P1：接入现有日线/分钟审计。** 将 11 月案例诊断改为通过通用内核生成问题与计划，特定 SHA 只写回归 fixture，不出现在通用核心。兼容原有任务收据及 20:05 任务，严守隔离不降级。
- **P2：可选、显式授权的来源恢复算子。** 按股票日分段、具备幂等/冷却/超时/断点；QMT 自有缓存写权限与项目写入权限分离。需要真实现场权限验收，未授权时保持计划预览。
- **P3：版本化候选和审核事务。** 经过真实购买校准及独立官方 DAY，候选数据新建私有目录、证明原始字节/行、完整恢复演练后，才允许按权限修改规范月文件及 H5 镜像。
- **P4：持久队列/GUI 与跨周期质量。** 历史遗留缺口自动发现但非自动强行修复，按规则类型、日期范围、股票数、来源、重试状态及证据等级可视化；定时增量与长周期质量验证分离。

**完成定义：** 至少针对两种不同日期、两个不相干的证券集合，通过同一接口检测/隔离/重放/生成私有候选并复核来源；证明未授权 0 下载/0 写入、原来源和旧收据不变、修复后不影响其他股票日、八周期声明与物理实际相符。仅把 2026-11-25 的九只股票诊断通了不算本目标完成。

## 8A. 跨日异常清单的稳定身份与证据版本（2026-11-25 新增决策）

通用质量问题的稳定身份由交易日、证券、周期、来源标识和质量规则版本组成；不能以某次回执的绝对路径、执行时间或当日股票名单作为事件身份。不同来源和不同规则要保留各自事件，同一事件在后续快照中可以有多个证据版本。

- **不可变问题身份**：用规范化 SHA256 生成稳定 incident ID；事件身份/规则版本一旦更改，须通过明确的迁移/关联规则，而非静默覆盖旧条目。规则实现升级不得偷偷把旧证据解释成已验收。
- **证据与认定分离**：诊断 JSON、生产回执、已接收候选 Parquet、原始被隔离 QMT 行情和独立官方 DAY 必须分别记录真实哈希范围；缺少任一独立证据时显示需要补证，不得替代。
- **版本与去重**：完全相同的观察可以幂等合并；同一事件的不同来源/快照变化应并列保留并标记复核。若已有 DETECTED 隔离，后一次仅表现为 INSUFFICIENT_EVIDENCE 或接口暂时可用，不可自动认定 RESOLVED。
- **异常与任务状态分离**：原始 producer_quarantined 仍为未结事件，不因同批次其他股票日正常接收、某条候选通过或任务退出码 0 解除；清单为空也不能自动说明全市场质量完全 PASS。
- **持久化授权独立**：第一阶段只读计算清单及其规范 SHA；将清单写成持久数据库是下一阶段的独立、版本化、可恢复的私有事务，不得借“生成报告”无意覆盖旧证据。任何自动补取行情或正式 Parquet/H5 合并仍需另一层独立授权。

这套能力必须兼容任意有界日期范围、任意受支持证券/周期及独立来源，并通过多日多股、同日多来源、多异常并存、证据版本冲突及未授权零写入的回归测试。2026-11-25 的九只股票只能作为其中一组用例。

## 8B. 原始来源文件的字节证明与独立真实性（2026-11-26 补充）

对每一份声明为 QMT 原生分钟、独立官方 DAY、购买校准参考的本地导出件，先在显式给定的私有目录内校验：相对路径范围、symlink/hardlink 与重复对象、文件大小上限、读取前后文件身份与修改时间、**实际文件字节 SHA256 与预期值**。路径越界、非法/重复 JSON 键或数据更改必须 fail-closed，不得进入后续验收。

各级认证语义严格分离：
- **LOCAL_BYTES_VERIFIED**：可证明本次所读本地文件字节与声明的 SHA 一致；不自动证明由指定供应商导出，也不证明文件声明的股票、日期、周期和实际内容相符。
- **PROVIDER_IDENTITY_AUTHENTICATED**：要有独立、可复核的供应商/签名/权限来源链；两个用户输入的不同 source_id 标签不能构成独立来源证明。
- **OFFICIAL_CONTENT_VERIFIED**：真正解析独立 DAY 文件，对证券、时点、复权、行结构、成交与实际交易日全集进行检验；不能凭本地文件名或哈希本身授予该标志。
- **MARKET_CANDIDATE_VALIDATED**：须分别通过原有完整时间网格、原购买源校准、六字段 OHLCVA、跨周期及物理完整性检验；前三级中任何一个 pass 都不允许省略此步。
- **PRODUCTION_COMMIT_APPROVED**：另行授权和可回滚物理事务，不能由取证程序本身签发。

取证程序应默认只读、无行情下载与任何项目文件写入，输出明示 SHA 的范围和尚未证明的来源关系。样本可以是任意交易日期/证券/八周期，但必须来自用户明确指定的本地私有文件，不得自动扫描用户全盘、上传文件或从付费行情源静默导出。真正的适配器需要在这一层之后，逐一实现独立数据格式解析与有效性验证。

## 8C. 已声明独立 DAY 来源的内容验证（2026-11-26 补充）

单独源文件的字节 SHA 核验之后，还必须对具有既定 schema 的 DAY 导出件执行**只读内容校验**，并与“提供商来源真实”和“全市场证券覆盖完整”分开：

- 使用本仓库已建立的 Arrow 八列物理契约，以北京时间将 ts 毫秒映射到交易日期，支持不同来源的合法证券代码规范化，拒绝重复股票日、缺失字段、非法 OHLC 区间、非有限价格与成交量额单边正值。
- 明确区分“这一份 DAY 导出中有一个有效目标证券日”与“本日证券全集已覆盖”。不能从标记 SH/SZ/BJ 的代码格式断言证券一定属于股票而非指数；需要交易所官方证券列表或经授权的完整性凭据。
- 对不存在 QMT 分钟缓存的股票日，允许**单独核对已有官方 DAY Parquet**；不应强制要求再提交一个不存在的 QMT 原始分钟文件，不能为通过验收而虚构数据。
- 文件的实际字节哈希必须在内容读取前后核对；来源 ID 和 SHA 均只是证据，单独任何一项都不能认证提供商身份、独立交易日历或允许修复入库。
- 内容验证器不得请求 QMT 历史下载、写正式 Parquet/H5 或更改此前的隔离；下一阶段才将真正的数据商身份与官方交易日股票全集独立接入。

这属于可复用的 DAY 专项物理检查插件，不是通用内核中硬编码 2026-11-25 或把 DAY 的格点套给全部八周期。必须在多日期/多证券及坏数据合成回归中证明 fail-closed，并在用户本机完成实际 ParquetFile 只读 E2E，才能声称真实文件内容适配器已通过。

## 8D. 真实 TDX DAY 覆盖状态与回执的可信内容链（2026-11-26 补充）

在一般来源文件字节校验（8B）和单日 Parquet 内容检查（8C）之上，原正式 `live_sync.py` 当前具有可复用的私有 TDX DAY 来源账本：`work/state.json`、`work/incremental/day/year=YYYY/YYYY-MM-DD.json` 和同名 Parquet。后续工具要将真实日线视作可信候选参考，必须先逐一核对三者的日期、规范路径、SHA、行数、基准源版本及量纲校准标识；**不能直接依据状态文件所称“已完成”就把 DAY 内容认定为提供商官方证明**。

- **日期与来源格式版本**：TDX DAY 覆盖模块只负责既有基准日之后、按其特定 `live_sync` 状态格式登记的数据；别的交易日范围、证券类别或来源必须选用其他适配器，不把这个基准日写成整个 A 股市场治理的永久硬编码。
- **互证链**：读取 state 与配对日回执的真实物理字节 SHA，对 entry 的路径/日期/rows/sha256/raw_zip_sha256 和回执一一对应；再读取 Parquet 全部行，根据实际 schema、北京时间、代码规范、去重、OHLCVA 等检查目标证券日；校验完整行数及读前读后 state、回执和 Parquet SHA 不变。
- **ZIP 来源严格区分**：`raw_zip_sha256` 在 state/receipt 中出现，仅能证明该哈希被**声明**；没有给出与回执一致的实际 ZIP 字节及来源认证时，`raw_zip_bytes_verified=false`。允许操作者明确指定一个本地已有 ZIP 文件的安全相对路径进行只读字节核验，不得自动搜索、下载或从用户账号补取；即使 ZIP 的 SHA 匹配，仍不能自动升级为交易所/提供商签名认证。
- **市场数据与权限**：单日参考股票存在不等于当天交易所全市场证券集合已被证明；独立日线内容有效也无法替代缺失的 QMT 241 根分钟行情。保留原九只股票日隔离以及正式校准/时间网格验证；状态、回执、官方 DAY 与规范 Parquet/H5 的写入权限分别受控。
- **验收**：新增可复用的跨日期/证券暂存账本审计适配器，使用真实临时文件正反测试、错误 SHA/状态/配对/日期/行数、读取期间状态竞争的 fail-closed 测试；在用户本机进一步运行真实 Arrow 文件端到端和当日 live 状态只读检查后，才算通过现场来源链核验。

## 8E. 可复用的交易日证券集合交叉对照与差异分桶（2026-11-26 补充）

对任何物理来源（例如已经在 state/receipt/Parquet 三方 SHA 固定的 TDX DAY 覆盖），必须把“物理 Parquet 行数”“能规范化为交易所代码的记录数”“候选股票数”“独立证券日全集”“真实有成交股票日”**严格分开**。代码形状或成交量不能单独认证股票身份；2026-11-25 的 DAY Parquet 5,572 行就是必须避免误用的真实案例，不能把行数当作全市场应交易股票集合。

通用对照器以**已认证字节但尚未认证供应商身份的源快照**和**另一份明确提供、字节 SHA 固定的声明参考清单**为输入：
- 参考清单按 `(trading_day, symbol, declared_source_id, trading_state)` 表示证券日事实声明，`TRADED`、`NO_TRADE`、`UNKNOWN` 分开；必须拒绝范围之外路径、符号链接、重复 JSON 键、重复证券、跨日期和 SHA 漂移。
- `FULL_DECLARED` 只表示文件作者**声称**覆盖完整；即使来源标签与 TDX 不同，也不等于获得了官方完整交易日集合证明或两份独立数据商身份认证。
- 差异必须稳定分桶：参考声明成交但物理 DAY 缺、参考声明成交但 DAY 为零、参考声明无成交而 DAY 为正、DAY 有代码但参考未列、双方均有成交，以及状态未知/无成交匹配。**不能把参考没有列出的代码直接叫作错误股票**；正式缺失股票日需要独立市场日历和证券清单来源确认。
- 两侧实际字节 SHA、state/receipt 版本及读取期间变化必须核对；报告哈希仅证明本轮诊断 JSON，不能伪装提供商签名。一个清单可以包含多个待核验事件，但不能在没有独立来源认证时关闭已有生产隔离。
- 默认仅输出只读报告，任何补取 QMT 分钟数据、修复候选生成、持久问题数据库写入或 Parquet/H5 提交仍受各自独立授权。

此能力须支持任意已有覆盖的合法日期、证券集合和来源快照版本，并以多日期、多证券、完整/局部参考、零成交、伪造来源声明、字节篡改和读取过程变化作为合成回归。现实参考清单若不存在，**必须明确说明无法开展真正的跨源认证**；不得在生产 DAY 源自身复制一份“独立”参考清单来虚构交叉验证通过。

## 8F. 声明来源证券日差异与通用异常队列的安全衔接（2026-11-26）

跨来源 DAY 对照（8E）只是数据*声明*的比较。若第二份清单尚未完成独立供应商身份和交易日证券全集验证，**不能**把该比较结果复用原来表示“独立来源确实存在行情冲突”的 `SOURCE_CONFLICT`，也不能认定某只股票已经合法停牌/缺失。

- `DECLARED_DAY_STATE_CONFLICT`：已 SHA 固定的两组**声明交易状态**相矛盾，记录 P2 待调查事实，而非 P1 已证实市场数据错误；必须留存两侧证据文件 SHA、参考声明覆盖范围及规范诊断 JSON SHA。
- `DECLARED_DAY_REFERENCE_UNCERTAIN`：另一参考清单未包含 DAY 中出现的代码，或该清单明确表示交易状态 UNKNOWN，记录 P3 的证据不足，不能自动判定是数据多出、证券退市或应当剔除。
- 双方声明一致但没有独立身份与覆盖全集时，不能把它当成官方市场质量 PASS；通用事件清单为空也不能自动解除旧隔离。
- 对照报告入队列前，需检验所有分桶互斥、各桶件数以及参考证券数和物理 DAY 规范代码数守恒；即使有人重算规范诊断 JSON SHA，错误的交叉核对统计也不得通过。
- 所有差异应通过既有 `market_quality_engine` 与 `market_quality_backlog` 的规则版本和稳定事件身份衔接，而不是建立一次性独立异常格式。原 QMT 每日生产回执的 1min 隔离可选择性只读并入，但需独立核对原隔离数、原 SHA 且永久保持自动关闭权限 false。
- 真正修复与持久化仍需完整独立凭据、正式候选重验及分离的 QMT/私有存储/正式合并权限；任何证据层的临时报告均不自动写入生产。

以上规则必须支持其他日期、证券、提供商声明与证据版本变更；保持原 2026-11-25 的 5,206 接收、9 隔离和 `PARTIAL` 门禁不变。

## 9. 维护约束

后续所有 AStockDataTools 行情开发/研究，应先核对本设计，技术决策优先选择**通用清洗算子、独立证据、版本化策略、跨日多股票回归、可回滚事务**。如果当前需求与本规范冲突，应在独立 PR 中解释影响并修订设计，经审核后再变更实现；不能通过临时硬编码、降校验阈值、禁用证书校验或修改历史收据绕过治理。

TLS/网络错误只属于工具链传输故障：应先重试、检查本地已有目标提交、使用受信任的 TLS/企业代理配置，固定远端 commit SHA 再继续；不能关闭 SSL 验证、私自切换未证实来源，或把 Git fetch 失败解释为市场数据损坏。
